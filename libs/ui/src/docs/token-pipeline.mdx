# Token pipeline

The token pipeline moves design tokens between the Plectrum UI Kit in Figma, this design-system repository, and the applications that install it.

- **Figma** holds the design decisions (colours, radii, shadows, transitions, focus).
- **The repository** imports them, generates CSS custom properties, documents them in this Storybook, and publishes versioned packages.
- **Applications** (iSHARE, iCRM) install a package version and reference tokens as `var(--pds-*)`.

Drift between Figma and CSS fails CI. No automated step writes the main Figma file.

Related pages:

- [Figma sync](?path=/docs/docs-token-pipeline-figma-sync--docs) — Figma → repo import, repo → Figma proposals, package distribution
- [CSS-first surface](?path=/docs/docs-token-pipeline-css-first-surface--docs) — the CSS contract for component authors
- **Foundations** — token browsers, rendered from the compiled CSS by `<pds-token-explorer>`

Constraints:

- Automated writes target Figma branches only. The main Figma file is edited and published by designers.
- Applications install a package version. Token values are never copied into an application repository.
- Code-owned tokens (spacing, typography, feature-specific values) compile into the same stylesheet as imported tokens.

## Reference

### Commands

```bash
npm run tokens:audit              # three-way Figma / v1 / SCSS + alias-map
npm run tokens:validate-preset    # every {token.path} in Plectrum_v1/ts
npm run tokens:check-prefix       # no new bare --spacing- / --text- / --font- decls
npm run tokens:build              # regenerate *.generated.scss + tokens.generated.ts
npm run tokens:lint               # --p-* decls, PrimeUI runtime imports, unknown --pds-*
npm run tokens:propose            # code-only tokens → proposed.dtcg.json
npm run tokens:apply -- --app scratch --dry-run
npm run pack:smoke                # pack tarballs and build a throwaway app
```

CI runs the audit, the prefix guard, `tokens:build && git diff --exit-code`, lint, the pack smoke test, and a packed-Storybook build. `tokens:validate-preset` is `continue-on-error` until `tokens.json` covers every PrimeNG path.
