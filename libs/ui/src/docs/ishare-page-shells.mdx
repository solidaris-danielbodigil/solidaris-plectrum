# Page shells

App-owned CSS bridges — not Core components. Owner: iSHARE. Status: app.

These four files in `libs/styles/src/01-settings/` hold iSHARE page-shell tokens and scoped `--p-*` bridges. They are not Angular components. Screens stay in `apps/ishare`; the design system only stores the token bridges so Storybook and the apps share one stylesheet.

Related catalogue pages: [Toolbar](?path=/docs/custom-components-toolbar--docs), [Delay Prediction Card](?path=/docs/patterns-ishare-delay-prediction-card--docs), [PrimeNG customizations](?path=/docs/docs-primeng-customizations--docs).

## When to use

- iSHARE affiliate search, dossier, and document-detail page chrome
- Scoped PrimeNG Card token bridges for the two-column dossier and the documents toolbar
- Page-specific sizes that must not leak into Core `01-settings` files

## When not to use

- Importing these tokens from iCRM or a new application — propose to the core team first
- Promoting the bridges to Core without a second consumer
- Adding a `libs/ui` wrapper for layout that the app template already owns with `o-flex` / `o-layout`

## Accessibility

- These files do not render UI. Keep the app screens semantic: page landmarks, labelled columns, and busy states on loading regions
- Do not replace heading structure with card chrome from a token bridge
- Filter and search controls in the documents toolbar keep their own accessible names
