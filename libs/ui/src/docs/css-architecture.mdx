# CSS architecture

All shared CSS lives in `libs/styles` and is layered with **ITCSS**. Class names follow **BEMIT**. Templates mix a component block with object and utility classes. Component SCSS does not restate layout that an `o-*` class already covers.

## Definition

**ITCSS** (Inverted Triangle CSS) is the folder order under `libs/styles/src/`. Earlier layers are broader and less specific. Later layers override them. A change belongs in exactly one layer.

**BEMIT** is BEM plus a namespace prefix. The prefix says which ITCSS layer owns the class.

SSOT order when a control is painted:

1. PrimeNG defaults
2. Plectrum theme (`providePlectrum()`)
3. `libs/styles` ITCSS — objects, then the scoped `c-` block, then utilities

## Process

How an author decides where a rule goes.

<Unstyled>
  <Story of={Figures.AuthoringOrder} />
</Unstyled>

```html
<div
  class="c-form-field o-flex o-layout--min-w-0"
  [class.o-flex--y]="layout() === 'vertical'"
  [class.o-layout--gap-1]="layout() === 'vertical'"
  [class.is-invalid]="invalid()"
>
  <span class="u-sr-only">({{ requiredLabel() }})</span>
</div>
```

`c-form-field` is the block. `o-flex` / `o-flex--y` / `o-layout--*` are the layout mix. `is-invalid` is state. `u-sr-only` is a utility. The SCSS file styles the block, the label and invalid colour — not `display: flex`.

## Rules

  <Story of={Figures.Rules} />
</Unstyled>

<Unstyled>
  <Story of={Figures.StaysInScss} />
</Unstyled>

Hard stops:

- Never write `display: flex`, `flex-direction`, `align-items` or `justify-content` in `06-components`.
- Never write gap, padding, margin or overflow in `06-components` when an `o-layout` modifier exists for that value.
- Never put a new `--pds-*` value inline. Add it in `01-settings` first.
- Never `@extend` or mixin an object class into a BEM file. The mix must be visible in the template.
- Never create a nested feature block (`c-affiliate-detail-drawer__name`). Prefix the **element** on the shared block (`c-drawer__affiliate-detail-name`).

### File naming

Components do not declare `styleUrl` — there is no colocated stylesheet. The BEM stylesheet is the `06-components` partial, and `pds:component` appends its `@forward` to `_components.core.scss`. The only exception is a `:host` display rule that cannot live in a global sheet under ViewEncapsulation — added by hand, with a comment saying why.

### BEM anatomy

```
.c-card                 block
.c-card__header         element
.c-card--featured       modifier
.c-card.is-loading      state (standalone class)
```

Elements use `__`. Modifiers use `--`. States use `is-` / `has-` on the same node. Do not nest a second block inside a block in SCSS — compose in HTML.

```scss
.c-card { }
.c-card__header { }
.c-card--featured { }
.c-card.is-loading { }
```

Column layout uses `o-flex` + `o-flex__item--{1–12}` (and `@{breakpoint}`). Bespoke `display: grid` stays in component SCSS and needs a comment.

`o-flex--y` is the column helper. Other flex-flow keys are generated from `settings.grid` — read them on Flex Grid, not from a handwritten list.

### Semantic border roles

Use a shared colour role in SCSS. Do not invent a feature-specific border alias.

<DocsTable
  headers={['Token', 'Typical use']}
  rows={[
    ['--pds-color-panel-border', 'Section dividers, list shell, bordered accordion'],
    ['--pds-color-card-border', 'p-card rings, selectable rows'],
    ['--pds-color-content-border', 'Nav shells, tiles, notes'],
    ['--pds-color-surface-border', 'Iconography cards, doc demos'],
  ]}
/>

In templates, pair `u-border-{side}` with `style="--pds-border-color: var(--pds-color-panel-border)"` when the utility default is not the role you need.

### PrimeNG

No scoped `--p-*` or `.p-*` overrides for button, stepper, tag, inputs, drawer, dialog, popover or menu. No `styleClass` on `p-drawer` / `p-dialog` roots. Overlays inside flex or `overflow-hidden` use `appendTo="body"`.

When a wrapper must win over PrimeNG chrome, prefer ITCSS order, then `:is()` / `:where()` on the scoped wrapper, then `@layer components`.
