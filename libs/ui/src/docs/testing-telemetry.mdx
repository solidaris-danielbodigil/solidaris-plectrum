# Testing telemetry

Exported API from `libs/ui/src/lib/testing-telemetry/` (re-exported on `@solidaris/ui`). Moderated user-testing capture only — never wire it to production analytics.

The host app provides `TESTING_TELEMETRY_ENABLED` from `environment.enableTestingTelemetry`. iSHARE does this in `app.config.ts` via `isTestingTelemetryEnabled()`.

## When to use

- Moderated user-testing sessions in a development build
- Stable `data-test` labels on interactive hosts for click capture
- JSON session download or CSV export after a session

## When not to use

- Production analytics or product telemetry
- Enabling the token in a production environment
- Treating telemetry identifiers as UI copy — do not run them through i18n

`pdsTelemetryLabel` takes a required string (the visible label or a stable test id). When the token is false the directive writes no attribute.

CSV columns: `event,target,label,timestamp,taskId,x,y,viewport_w,viewport_h,route`. Values are escaped when they contain commas, quotes, or newlines.

Click capture uses `data-telemetry-id` / `data-test` via `resolveClickTarget`. Idle events fire after a pause on the last click target. Do not connect this service to a production analytics endpoint.

## Accessibility

- Telemetry labels are analytics identity, not UI copy — do not i18n them
- `data-test` must not replace `aria-label`, visible text, or `aria-labelledby`
- Facilitator session controls live in the app shell, not in this library API
