Plectrum is the Solidaris design system — shared components, tokens and layout for every application. This Storybook is the published guidance. Figma is where you design; it is not a second set of rules.

Core components are shared. Candidate and app-specific work stays with the application team until the core team promotes it. Every component page shows status and owner — [Contribute → Status and owner](?path=/docs/get-started-contribute--docs#status-and-owner).

Each application team has its own repository. Download three folders from the design-system repository into that repository: [`.ai`](https://github.com/solidaris-danielbodigil/solidaris-plectrum/tree/main/.ai) at the root, [`.cursor/agents`](https://github.com/solidaris-danielbodigil/solidaris-plectrum/tree/main/.cursor/agents) for Cursor, and [`.github/agents`](https://github.com/solidaris-danielbodigil/solidaris-plectrum/tree/main/.github/agents) for VS Code. Agents load `.ai/README.md` and the Plectrum coordinator from there. A sample request is on [AI strategy → Subagents](?path=/docs/docs-ai-strategy--docs#subagents). The packages do not carry these folders. [AI strategy → Team repositories](?path=/docs/docs-ai-strategy--docs#team-repositories).

## Get help

A typo or a wrong example is a pull request. A missing component, variant or token is a [proposal](https://github.com/solidaris-danielbodigil/solidaris-plectrum/issues/new?template=proposal.yml). Say what the screen must do, what you already tried, and attach a Figma link. The core team answers: use what exists, they will build it, or your team builds it and owns it.
