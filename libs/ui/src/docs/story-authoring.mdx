# Writing stories

> **In short.** For the core team. One story per state, written next to the component; play functions assert what a user sees, axe checks every story, and every interactive component has a keyboard story. The component page renders its metadata, so the MDX adds canvases, not prose.

A story is one rendered state of a component. Developers write stories next to the component; designers review them against the Figma design.

The paths, helpers and commands below are those of the Plectrum repository. In an application, follow the same principles in your local Storybook — see [Build with Plectrum → Set up Storybook and tests](?path=/docs/get-started-use-plectrum-in-an-app--docs#set-up-storybook-and-tests).

## Definition

**CSF** (Component Story Format) is the TypeScript file that renders states. **Attached MDX** is the prose page that embeds those states as canvases. Storybook discovers both through `libs/ui/.storybook/main.ts`. Agents author against Storybook MCP when `npm run storybook` is running — see [How agents work → Storybook MCP](?path=/docs/docs-ai-strategy--docs#storybook-mcp).

## Documentation source

The `.metadata.ts` is the single source of a component's documentation: API table, status and owner, usage, anatomy, accessibility, lead paragraph and Figma link. The MDX embeds one figure per block and adds only headings, canvases, prose about the examples and visuals. `npm run docs:check` fails a page that restates a block as prose. Preview layout defaults to `padded`. A fullscreen or `100dvh` wrapper belongs on app-chrome catalogue stories, never on `meta.decorators` — otherwise every figure on the docs page becomes a blank viewport. Token catalogues with a sticky toolbar embed `<Story>`, not `<Canvas>`, so the toolbar can pin against the docs scroll.

CSS-only blocks (Accordion, Timeline, Drawer, Detail List, Skeleton Slot) have a `.metadata.ts` for the same reason, even though there is no Angular class to ship it with. Pages without a metadata file — foundations, process — use `doDontStory({ dos, donts })` with hand-authored entries, as this page does above.

The rule itself lives in `.ai/rules/03-storybook.md` §3.

### Custom CSS layer

One-off spacing on a wrapper we own stays an **object class** (`o-layout`). The bordered accordion is a reusable variant, so it lives in ITCSS:

- Tokens and `--p-accordion-*` bridges: `libs/styles/src/01-settings/_settings.accordion.scss`
- Stacked panel radii and disabled cursor: `libs/styles/src/06-components/_components.accordion.scss`

```html
<p-accordion
  class="c-accordion c-accordion--bordered o-layout o-layout--full-width o-layout--min-w-0"
  expandIcon="bi bi-chevron-down"
  collapseIcon="bi bi-chevron-up"
>
  <p-accordion-panel value="0">
    <p-accordion-header>Certificat ITT</p-accordion-header>
    <p-accordion-content>Date de réception 24/11/2025</p-accordion-content>
  </p-accordion-panel>
</p-accordion>
```

```scss
// libs/styles/src/01-settings/_settings.accordion.scss
.c-accordion--bordered {
  --p-accordion-panel-border-width: 1px;
  --p-accordion-panel-border-color: var(--pds-color-panel-border);
  --p-accordion-header-background: var(--pds-color-accordion-bordered-section-bg);
  --p-accordion-header-padding: var(--pds-space-accordion-bordered-padding);
  --p-accordion-content-padding: var(--pds-space-accordion-bordered-padding);
}
```

Do **not** write this:

```scss
// Wrong — fights PrimeNG internals and hard-codes a value
.p-accordionpanel {
  border: 1px solid #e7e7e7 !important;
  border-radius: 8px;
}
```

### Story file

The catalogue pair is [Accordion](?path=/docs/custom-components-accordion--docs). CSF lives in `libs/ui/src/lib/accordion/accordion.stories.ts`. There is no Angular wrapper — stories import `AccordionModule` from `primeng/accordion` with a relative path, not `@solidaris-danielbodigil/pds-ui`. Open **Show code** on the canvases above for the live Angular template.

The canvases above are `Default`, `Bordered`, `Collapsed`, and `Disabled`. `Stacked` is a fifth export on the same file. Bordered vs Default is two templates — the class is in the HTML, not an args toggle.

~~~ts
// libs/ui/src/lib/accordion/accordion.stories.ts
import type { Meta, StoryObj } from '@storybook/angular-vite';
import { AccordionModule } from 'primeng/accordion';
import { Tag } from 'primeng/tag';

interface AccordionStoryArgs {
  title: string;
  statusLabel: string;
  expanded: boolean;
  disabled: boolean;
}

const STOCK_CLASS = 'o-layout o-layout--full-width o-layout--min-w-0';
const BORDERED_CLASS = 'c-accordion c-accordion--bordered o-layout o-layout--full-width o-layout--min-w-0';

const meta: Meta<AccordionStoryArgs> = {
  title: 'Custom components/Accordion',
  parameters: { layout: 'padded' },
  argTypes: {
    title: { control: 'text', description: 'Panel header label.' },
    statusLabel: {
      control: 'text',
      description: 'Status tag next to the header.',
    },
    expanded: {
      control: 'boolean',
      description: 'When true, the panel value is set so the section is open.',
    },
    disabled: {
      control: 'boolean',
      description: 'Disables p-accordion-panel.',
    },
  },
  args: {
    title: 'Certificat ITT',
    statusLabel: 'Accepté',
    expanded: true,
    disabled: false,
  },
};

export default meta;

type Story = StoryObj<AccordionStoryArgs>;

function accordionTemplate(hostClass: string): string {
  return `
    <p-accordion
      class="${hostClass}"
      [value]="expanded ? '0' : undefined"
      expandIcon="bi bi-chevron-down"
      collapseIcon="bi bi-chevron-up"
    >
      <p-accordion-panel value="0" [disabled]="disabled">
        <p-accordion-header>
          <span class="o-flex o-flex--align-items-center o-layout o-layout--gap-2">
            <span>{{ title }}</span>
            <p-tag severity="success" icon="bi bi-check-lg" [value]="statusLabel" />
          </span>
        </p-accordion-header>
        <p-accordion-content>
          <p class="o-layout o-layout--margin-0">Date de réception 24/11/2025</p>
        </p-accordion-content>
      </p-accordion-panel>
    </p-accordion>
  `;
}

function renderWithClass(hostClass: string): Story['render'] {
  return (args) => ({
    props: args,
    moduleMetadata: { imports: [AccordionModule, Tag] },
    template: accordionTemplate(hostClass),
  });
}

export const Default: Story = {
  render: renderWithClass(STOCK_CLASS),
};

export const Bordered: Story = {
  render: renderWithClass(BORDERED_CLASS),
};

export const Collapsed: Story = {
  render: renderWithClass(BORDERED_CLASS),
  args: { expanded: false },
};

export const Disabled: Story = {
  render: renderWithClass(BORDERED_CLASS),
  args: { disabled: true },
};
~~~

## Keyboard stories

Every Plectrum Angular component with a button, a link, a `tabindex` or a `keydown` handler has a story tagged `keyboard`. It proves the lines of `accessibility.keyboardSupport` that Plectrum owns, with key presses: Tab order, Enter and Space, Escape, and where focus goes when something opens or closes. Keyboard models PrimeNG already implements — Tree arrows, Accordion headers, the Dialog and Drawer focus trap — are not tested again.

## Reference

### File location

```
libs/ui/src/lib/component-name/
├── component-name.component.ts
├── component-name.stories.ts
└── component-name.mdx
```

PrimeNG-first layers that only add a BEMIT class skip the wrapper component. Accordion is that case: `libs/ui/src/lib/accordion/` has `accordion.stories.ts` and `accordion.mdx` only.

Process pages such as this one live in `libs/ui/src/docs/`. Figure content that MDX cannot pass as props lives in a sibling `*.stories.ts` tagged to stay out of the sidebar.

Do not end a docs file name in `.stories.mdx`: Storybook would read it as a story file.

### Testing

A story without assertions only checks that it renders; add a `play` function to test behaviour. The sidebar testing widget runs on `@storybook/addon-vitest`; CI runs `@storybook/test-runner` (`npm run test-storybook`). See [Storybook — How to test UIs](https://storybook.js.org/docs/writing-tests).

### Commands
