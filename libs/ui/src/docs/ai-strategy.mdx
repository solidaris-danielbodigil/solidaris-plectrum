# AI strategy

Agents work against **contracts**, not against a full-repo read. Contract-Driven Development (CDD) gives a typed metadata schema, a generated component index, and short protocols. Humans still own Figma, Storybook and the CSS.

## Definition

A **contract** is a machine-readable file next to the thing it describes. Agents load the index, then Storybook MCP when the catalogue is running, then one metadata file, then a protocol. They do not invent a second design system.

## Process

How an agent is expected to work. Same order as `.ai/contracts/protocols/query-protocol.md`.

<Unstyled>
  <Story of={Figures.QueryOrder} />
</Unstyled>

The agent is the **default operator** for this flow: it scaffolds, fills the metadata, and runs the token scripts itself. Nothing here is a manual chore — `pds:component` regenerates the index when it finishes, a Cursor hook (`.cursor/hooks/regenerate-contracts-index.mjs`) re-runs `generate-index` after edits under `libs/ui`, and CI fails when the committed index is stale or when a docs page restates a metadata block (`npm run docs:check`). Doing a step by hand stays possible; it is a choice, not a requirement.

## Storybook MCP

`@storybook/addon-mcp` serves `http://localhost:6006/mcp` while `npm run storybook` is running. Cursor and VS Code register that URL. No running Storybook → no MCP; use `index.json`.

The index stays. MCP is the live catalogue (stories, Controls, docs pages). The index is the offline map (paths, BEM, `uses` / `usedBy`, status, owner). `tokens.consumed` and `aiHints` stay in `.metadata.ts`.

### Create a component

MCP does not scaffold. Pre-flight is still PrimeNG MCP → Figma MCP → `index.json` → `docs-list` (when Storybook is up) → `pds:component`. After the stub exists, `docs-show` a sibling (Copyable Text, Form Field) and copy that CSF + MDX shape. Gate with `contracts:check`, `docs:check`, `test-storybook`.

### Create stories

1. `docs-show` the component — do not add a Control that is missing from `.metadata.ts` `props`.
2. `get-storybook-story-instructions`, then apply [Writing stories](?path=/docs/docs-writing-stories--docs): colocated CSF, required states, `play` from `story-tests.ts`.
3. `stories-preview` the new canvases.
4. `npm run test-storybook` — MCP cannot run play or a11y tests.

## Reference

### Metadata file

Every `libs/ui` component has `{name}.metadata.ts` next to the class. Shape: `ComponentMetadata` in `.ai/contracts/schema/component.metadata.ts`. It is also the single source of truth for the component's docs page — the MDX embeds figures that render these blocks (`pds-docs-status`, `pds-docs-contract`); see [Writing stories → Documentation source](?path=/docs/docs-writing-stories--docs#documentation-source). `npm run docs:check` fails a page that restates a block by hand.

Import the type from `@solidaris/contracts`. Export a const (`EmptyStateMetadata`, …). `libs/ui/src/lib/index.ts` re-exports metadata with the component.

### Index

`npm run generate-index` runs `tools/scripts/generate-index.ts`. It walks `libs/ui/src/lib`, reads imports and the colocated `.metadata.ts`, and writes `.ai/contracts/index.json`. The output is content-stable — `meta.generated` only advances when the content changed — so CI regenerates the index on every push and fails when the committed file is stale, the same pattern as the generated token files. `index.json` is the offline map. Storybook MCP at `http://localhost:6006/mcp` is the live catalogue when `npm run storybook` is running.

### Scaffold

```bash
npm run pds:component     # interactive: name, category, type, optional PrimeNG wrap
                          # regenerates .ai/contracts/index.json when it finishes
npm run generate-index    # manual run — only needed after hand-editing or deleting
```

`pds:component` creates the Angular files (no colocated stylesheet — see [CSS architecture](?path=/docs/docs-css-architecture--docs)), the `_components.{name}.scss` partial plus its `@forward` in `_components.core.scss`, a stories stub, and a `.metadata.ts` that already imports `ComponentMetadata` — then regenerates the index itself. Fill usage, tokens and aiHints before review; by default the agent does that as part of the task.
