# Design with Plectrum

This Storybook is the published guidance: when to use a component, which variant to pick, and how it behaves. Figma is the authoring library. If the two disagree, follow this Storybook and open a proposal.

You do not need the repository to design a screen. Enable these four libraries. Do not draw new components on the main kit.

  <Story of={Figures.Libraries} />
</Unstyled>

Fonts are Agenda for headings and Open Sans for text. They ship with the libraries. Do not substitute another family.

Zeroheight was an earlier site. Start here.

## Build a simple form

1. Open [Find a component](?path=/docs/start-here-catalogue--docs) and choose Form Field, not a new input.
2. In the PrimeNG kit, place InputText inside the Form Field component from the custom-components library.
3. Use the variants this Storybook documents: label, hint, required, invalid. Open the component page and the Figma component, not the whole file.
4. Check the narrow layout. Stack the label above the control. Do not shrink the type below the body role.
5. Write the error in the same language as the label, and say how to fix it.
6. Hand off the frame link plus the Storybook page. A developer should not have to guess which variant you meant.

## When nothing fits

Open a [proposal](https://github.com/solidaris-danielbodigil/solidaris-plectrum/issues/new?template=proposal.yml). Attach the frame, say which components you tried, and what the screen must do. Application designers work on a `proposals/{app}` branch. They do not edit the Primitive or Semantic collections, and they do not add a component to the main kit.
