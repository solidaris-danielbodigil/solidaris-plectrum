# Design with Plectrum

This Storybook documents the current implementation, its reuse scope, variants and behaviour. Figma is where designs are authored. A reviewed design in Custom components may propose a future version; [Contribute](?path=/docs/get-started-contribute--docs#start-from-a-reviewed-figma-design) explains how Core reviews, implements and releases it.

You do not need the repository to design a screen. Enable these four libraries. Do not draw new components on the main kit.

## When nothing fits

For a shared gap, open a [proposal](https://github.com/solidaris-danielbodigil/solidaris-plectrum/issues/new?template=proposal.yml). Attach the Custom components frame, say which PrimeNG and Plectrum components you tried, and what the screen must do. Application designers and the design team may propose a candidate in **PLECTRUM · Custom components**. Record a design-team review if one already happened. Any new shared token variable belongs in **Plectrum DS · PrimeNG v21**, through a separate reviewed token branch. Core records the decision before a component enters the shared catalogue.

An application team may build and deliver a local component without waiting for that decision. It remains owned by the application until Core reviews it for sharing. See [Build with Plectrum](?path=/docs/get-started-use-plectrum-in-an-app--docs) for the local setup and checks.
