# Design with Plectrum

This Storybook documents the current implementation, its reuse scope, variants and behaviour. Figma is where designs are authored. A reviewed design in Custom components may propose a future version; [Contribute](?path=/docs/get-started-contribute--docs#start-from-a-reviewed-figma-design) explains how Core reviews, implements and releases it.

You do not need the repository to design a screen. Enable these four libraries. Do not draw new components on the main kit.

## When nothing fits

Open a [proposal](https://github.com/solidaris-danielbodigil/solidaris-plectrum/issues/new?template=proposal.yml). Attach the Custom components frame, say which PrimeNG and Plectrum components you tried, and what the screen must do. Application designers and the design team may propose a candidate in **PLECTRUM · Custom components**. Record a design-team review if one already happened. Any new token variable belongs in **Plectrum DS · PrimeNG v21**, through a separate reviewed token branch. Core records the implementation decision before the component is built or submitted.

The current candidate workflow still requires Core approval before scaffolding. The planned separation between local application development and Core mutualisation is described in [Planned onboarding](?path=/docs/get-started-use-plectrum-in-an-app--docs#planned-onboarding).
