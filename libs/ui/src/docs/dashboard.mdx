# Dashboard

> **In short.** For the core team. The <a href={DASHBOARD_URL}>Plectrum dashboard</a> is where Core sees whether the design system is used, whether the agent helps and what to do next. It is built from facts already committed in the repository plus the usage reports applications send; the recommendations are computed in your browser, with today's date. This page says what each screen answers and what to do with the answer.

Numbers that belong to a release live in Storybook. Numbers about *teams* — who uses what, whose submission is waiting, which agent search fails — live on the dashboard, because they change daily and should not be frozen into a release bundle.

## Open it

Published beside this Storybook at <a href={DASHBOARD_URL}>{DASHBOARD_URL}</a>, and built on every pull request. Locally, the data is generated first and the dashboard is served from the same checkout:

<Source language="bash" code={`npm run start:dashboard   # insights:generate, then the dev server
npm run insights:generate # regenerate the data without restarting`} />

Routing is hash-based, so every section and every drill-down is a link you can paste into an issue.

The generated module is **gitignored**. It is a pure function of the checkout, so committing it would change on every commit and churn every pull request. Reviewing it in a diff is not a thing you have to do.

## What a recommendation carries

<Unstyled><Story of={Figures.Card} /></Unstyled>

Recommendations are deduplicated by a stable `rule:subject` id and ranked by severity, applications affected and volume. The same id stays the same between runs, so you can refer to one in an issue.
