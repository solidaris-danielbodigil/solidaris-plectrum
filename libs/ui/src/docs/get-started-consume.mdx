# Use Plectrum in an app

An application installs versioned packages and consumes CSS custom properties. No token values are copied; no build scripts are required in the application repository. A sample application in `tools/packaging/consumer-app/` is used to verify package installation — CI packs the libraries and builds that app against the tarballs on every push (`npm run pack:smoke`).

**Current state (pre-release).** All packages are at `0.1.0` in their `package.json`, and no version has been published to a registry yet — [What's new](?path=/docs/docs-what-s-new--docs) lists the pending changesets and an empty *Released* section. The `Release` workflow (Changesets + `npm run release`) is configured and publishes once a version PR merges on `main`; until then applications install **packed tarballs**:

```bash
# in the design-system repository
npm run pack:libs       # builds plectrum + ui, npm-packs all packages into tools/packaging/.tarballs/
```

```bash
# in the application — install the tarballs plus the PrimeNG peers
npm install ./path/to/solidaris-ui-0.1.0.tgz ./path/to/solidaris-plectrum-0.1.0.tgz ./path/to/solidaris-styles-0.1.0.tgz primeng @primeuix/themes
```

After the first release the same three packages install from the registry, and nothing below changes:

```bash
npm install @solidaris/ui @solidaris/plectrum @solidaris/styles primeng @primeuix/themes
```

The three `@solidaris/*` packages version together (a fixed Changesets group) — always upgrade them as a set.

## Wire the stylesheet

`angular.json` — resolve the ITCSS source from the package:

```json
"stylePreprocessorOptions": {
  "includePaths": ["node_modules/@solidaris/styles/src"]
}
```

`src/styles.scss` — the whole system is one `@use`:

```scss
@use '01-settings/settings.prefix' as *;
@use 'main';
```

## Boot the theme

```ts
// src/app/app.config.ts
import { ApplicationConfig, provideZoneChangeDetection } from '@angular/core';
import { provideAnimationsAsync } from '@angular/platform-browser/animations/async';
import { providePlectrum } from '@solidaris/plectrum';

export const appConfig: ApplicationConfig = {
  providers: [
    provideZoneChangeDetection({ eventCoalescing: true }),
    provideAnimationsAsync(),
    providePlectrum(),
  ],
};
```

`providePlectrum()` registers the PrimeNG theme and emits every `--p-*` custom property. The generated `--pds-*` tokens fall back to literals, so styles render even before the theme boots — but PrimeNG components need the provider.

## First component

The sample application renders one Core component around one PrimeNG input. This is `tools/packaging/consumer-app/src/app/app.ts` with the `pInputText` directive added so the PrimeNG theme visibly applies:

```ts
// src/app/app.ts
import { Component } from '@angular/core';
import { InputText } from 'primeng/inputtext';
import { FormFieldComponent } from '@solidaris/ui';

@Component({
  selector: 'app-root',
  imports: [FormFieldComponent, InputText],
  template: `
    <pds-form-field label="Member number" inputId="member" hint="Ten digits, no spaces">
      <input pInputText id="member" type="text" autocomplete="off" />
    </pds-form-field>
  `,
})
export class App {}
```

`ng serve` shows a labelled, themed field: the label and hint come from `pds-form-field` ([Form Field](?path=/docs/custom-components-form-field--docs)), the input chrome from the Plectrum preset. Every `pds-*` component is exported from the `@solidaris/ui` root — the component's docs page names the class to import.

## Build screens

PrimeNG components use the Plectrum preset as-is ([theme gallery](?path=/docs/primeng-actions--docs)). Import Core `pds-*` components from `@solidaris/ui` — [Component status](?path=/docs/docs-component-status--docs) lists each one. Layout with `o-flex` / `o-layout`, chrome with `u-*`, values via `var(--pds-*)`.
