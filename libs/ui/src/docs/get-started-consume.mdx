# Build with Plectrum

Set up an Angular application with the Plectrum theme, a local Storybook and the Plectrum checks.

<Unstyled><Story of={Figures.InstallFlow} /></Unstyled>

<h2 id="prerequisites" className="c-docs-onboarding__step-title o-flex o-flex--align-center o-flex--gap-md"><span className="c-docs-onboarding__step-index p-badge p-badge-xl p-badge-circle" aria-hidden="true" />Prerequisites</h2>

- A repository created from the <a href={`${REGISTRY.repository}/tree/main/tools/consumers/starter`}>Plectrum starter</a>, or an existing Angular application.
- Node {workspacePackage.engines.node}.

In `package.json`, set `plectrum.team` and `plectrum.application` to lowercase IDs (for example `ishare`), and `plectrum.repository` to the repository URL. Pick your own IDs to start; [register them](?path=/docs/get-started-contribute--docs#register-your-team) before you submit a component or a usage report.

Run `npm install`. Keep the three runtime packages on the same version.

<h2 id="initialize-the-team-toolkit" className="c-docs-onboarding__step-title o-flex o-flex--align-center o-flex--gap-md"><span className="c-docs-onboarding__step-index p-badge p-badge-xl p-badge-circle" aria-hidden="true" />Initialize the team toolkit</h2>

After `npm install`, the `plectrum bootstrap` script (a `postinstall` step) adds the Plectrum setup to your repository:

| Path | Contents |
| --- | --- |
| `.plectrum/config.json` | Team identity and source paths |
| `src/styles/` | Local ITCSS layers |
| `.storybook/`, `vitest.config.mts`, `angular.json` | Storybook and test setup |
| `.ai/`, `.cursor/`, `.github/`, `.vscode/` | Editor instructions, agents, MCP and the CI workflow |
| `.githooks/pre-commit` | Token check before each commit |

Commit these files with `package-lock.json`. If npm scripts are disabled, run `npm run pds:bootstrap`.

Check the identity and source paths in `.plectrum/config.json`. Keep your own instructions in separate files: `plectrum update` rewrites the generated ones after an upgrade.

<h2 id="wire-the-stylesheet" className="c-docs-onboarding__step-title o-flex o-flex--align-center o-flex--gap-md"><span className="c-docs-onboarding__step-index p-badge p-badge-xl p-badge-circle" aria-hidden="true" />Wire the stylesheet</h2>

Plectrum styles are already loaded. Put your own styles in the local ITCSS layers:

```text
src/styles/
  01-settings/_index.scss
  02-tools/_index.scss
  03-generic/_index.scss
  04-elements/_index.scss
  05-objects/_index.scss
  06-components/_index.scss
  07-utilities/_index.scss
  08-trumps/_index.scss
```

`src/styles/main.scss` loads each shared layer before your local one. Do not copy shared tokens into these files. A token only your application needs goes in a local token file, for example `src/styles/01-settings/_settings.tokens.scss`, listed under `paths.localTokenFiles` in `.plectrum/config.json`.

The Agenda and Open Sans fonts come with `pds-styles`, and `bootstrap-icons` is installed.

<h2 id="boot-the-theme" className="c-docs-onboarding__step-title o-flex o-flex--align-center o-flex--gap-md"><span className="c-docs-onboarding__step-index p-badge p-badge-xl p-badge-circle" aria-hidden="true" />Boot the theme</h2>

`src/app/app.config.ts` already calls `providePlectrum()`. In an existing application, add `providePlectrum()` and `provideAnimationsAsync()` to your providers.

<h2 id="first-component" className="c-docs-onboarding__step-title o-flex o-flex--align-center o-flex--gap-md"><span className="c-docs-onboarding__step-index p-badge p-badge-xl p-badge-circle" aria-hidden="true" />First component</h2>

Run `npm start`, then import a Core component in a screen:

```ts
import { Component } from '@angular/core';
import { InputText } from 'primeng/inputtext';
import { FormFieldComponent } from '@solidaris-danielbodigil/pds-ui';

@Component({
  selector: 'app-root',
  imports: [FormFieldComponent, InputText],
  template: `
    <pds-form-field
      label="Member number"
      inputId="member"
      hint="Ten digits, no spaces"
      requiredLabel="obligatoire"
    >
      <input pInputText id="member" type="text" autocomplete="off" />
    </pds-form-field>
  `,
})
export class App {}
```

More components: [Find a component](?path=/docs/start-here-catalogue--docs).

<h2 id="set-up-storybook-and-tests" className="c-docs-onboarding__step-title o-flex o-flex--align-center o-flex--gap-md"><span className="c-docs-onboarding__step-index p-badge p-badge-xl p-badge-circle" aria-hidden="true" />Set up Storybook and tests</h2>

| Command | Does |
| --- | --- |
| `npm run pds:storybook` | Starts your Storybook |
| `npm run pds:build-storybook` | Builds a static Storybook |
| `npm run pds:test:unit` | Runs the unit tests |
| `npm run pds:test:stories` | Runs story interactions and accessibility checks |

Run `npx playwright install chromium` once before the tests. Your Storybook documents your application's components; shared ones are documented here.

Create a component with `npm run pds:component -- --name <name>`. You get the component, a story, a unit test, metadata, styles in `06-components` and an evidence checklist to complete.

<h2 id="validate" className="c-docs-onboarding__step-title o-flex o-flex--align-center o-flex--gap-md"><span className="c-docs-onboarding__step-index p-badge p-badge-xl p-badge-circle" aria-hidden="true" />Validate</h2>

```sh
npm run pds:check:ci
npm run build
npm run pds:test:unit
npm run pds:test:stories
```

`npm run pds:check:ci` checks tokens, metadata and generated files. The generated CI workflow runs the same commands; give your repository read access to the Plectrum packages so it can install them.

## Report usage

A usage report lists the Plectrum components your application uses. Core reads it to plan changes, and it fills the **Used in** column of [Find a component](?path=/docs/start-here-catalogue--docs).

Reporting is on by default: after each push to `main`, the generated CI workflow sends the report as a pull request on the Plectrum repository. It starts once your team is [registered](?path=/docs/get-started-contribute--docs#register-your-team) and the repository has a `PLECTRUM_ADOPTION_TOKEN` secret, a GitHub token that can open pull requests on the Plectrum repository. Until then, the CI run shows a warning instead of failing. To opt out, set `reporting.enabled` to `false` in `.plectrum/config.json`.

Your local Storybook has a **Plectrum / Setup** page that shows what is still missing; `plectrum doctor` prints the same status. To check the report itself, run the first command below.

## Upgrade

Upgrade the three runtime packages together, then run `plectrum update` and the checks. [What's new](?path=/docs/docs-what-s-new--docs) lists the changes.

## Before you invent

Look in PrimeNG and Core first. If nothing fits, build the component in your application; you do not need Core's approval. Propose it to Core when other teams could use it.
