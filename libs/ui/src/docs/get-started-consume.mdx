# Use Plectrum in an app

An application installs versioned packages and consumes CSS custom properties. No token values are copied; no build scripts are required in the application repository. The reference implementation of everything below is `tools/packaging/consumer-app/` — CI builds it against packed tarballs on every push.

```bash
npm install @solidaris/ui @solidaris/styles @solidaris/plectrum primeng @primeuix/themes
```

The three `@solidaris/*` packages version together — always upgrade them as a set.

## Wire the stylesheet

`angular.json` — resolve the ITCSS source from the package:

```json
"stylePreprocessorOptions": {
  "includePaths": ["node_modules/@solidaris/styles/src"]
}
```

`src/styles.scss` — the whole system is one `@use`:

```scss
@use '01-settings/settings.prefix' as *;
@use 'main';
```

## Boot the theme

```ts
// app.config.ts
import { ApplicationConfig, provideZoneChangeDetection } from '@angular/core';
import { provideAnimationsAsync } from '@angular/platform-browser/animations/async';
import { providePlectrum } from '@solidaris/plectrum';

export const appConfig: ApplicationConfig = {
  providers: [
    provideZoneChangeDetection({ eventCoalescing: true }),
    provideAnimationsAsync(),
    providePlectrum(),
  ],
};
```

`providePlectrum()` registers the PrimeNG theme and emits every `--p-*` custom property. The generated `--pds-*` tokens fall back to literals, so styles render even before the theme boots — but PrimeNG components need the provider.

## Build screens

- PrimeNG components as-is — the Plectrum preset already styles them. Check [PrimeNG customizations](?path=/docs/docs-primeng-customizations--docs) for the few intentional deviations.
- `pds-*` components from [Custom components](?path=/docs/custom-components-empty-state--docs) — import from `@solidaris/ui`.
- Layout with `o-flex` / `o-layout` classes, visual chrome with `u-*` utilities, values via `var(--pds-*)` — never hardcode a hex or px. The catalogues live under **Foundations**.
