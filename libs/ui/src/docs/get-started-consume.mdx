# Build with Plectrum

An application installs versioned packages and consumes CSS custom properties. No token values are copied; no build scripts are required in the application repository. A sample application in `tools/packaging/consumer-app/` is used to verify package installation — CI packs the libraries and builds that app against the tarballs on every push (`npm run pack:smoke`).

**Current install.** The packages are at **1.0.0**, released **2026-09-14**. [What's new](?path=/docs/docs-what-s-new--docs) lists that version under Released, and there are no pending changesets. npm publish is not switched on yet (`release.yml` opens the version pull request only), so applications install **packed tarballs** of 1.0.0:

```bash
# in the design-system repository
npm run pack:libs       # builds plectrum + ui, npm-packs all packages into tools/packaging/.tarballs/
```

```bash
# in the application — install the tarballs plus the PrimeNG peers
npm install ./path/to/solidaris-ui-1.0.0.tgz ./path/to/solidaris-plectrum-1.0.0.tgz ./path/to/solidaris-styles-1.0.0.tgz primeng @primeuix/themes
```

When publish is switched on, the same three packages install from the registry. Nothing else on this page changes:

```bash
npm install @solidaris/ui @solidaris/plectrum @solidaris/styles primeng @primeuix/themes
```

Supported peers: Angular `^21`, PrimeNG `^21`, `@primeuix/themes` `^2`. The three `@solidaris/*` packages version together — always upgrade them as a set.

## Agent files

Download these folders from the design-system repository into the application repository. Place `.ai` at the root. Place the agent folders at the same paths the editors expect.

- [`.ai`](https://github.com/solidaris-danielbodigil/solidaris-plectrum/tree/main/.ai) — rules, skills and contracts. How to address Plectrum: [AI strategy → Subagents](?path=/docs/docs-ai-strategy--docs#subagents).
- [`.cursor/agents`](https://github.com/solidaris-danielbodigil/solidaris-plectrum/tree/main/.cursor/agents) — Cursor subagents. Start with Plectrum.
- [`.github/agents`](https://github.com/solidaris-danielbodigil/solidaris-plectrum/tree/main/.github/agents) — the same roles for VS Code.

How a team keeps them current: [AI strategy → Team repositories](?path=/docs/docs-ai-strategy--docs#team-repositories).

The Storybook **Preset** control (`v1` / `v0.6`) switches the theme inside this catalogue. It is not the package version. `providePlectrum()` with no argument uses preset v1.

Moved from a 0.x preset? Find every renamed input on [What's new](?path=/docs/docs-what-s-new--docs).

## Fonts, icons and browsers

Agenda ships as four `.woff2` files at `libs/assets/fonts/agenda` in the design-system repository. Copy that folder into your app's own assets, and add it to `angular.json` so `/assets/fonts/agenda/*.woff2` resolves.

Open Sans is not bundled. Load it yourself — a font service link or a self-hosted package both work — and make sure it is available before your app renders.

Install `bootstrap-icons`, then add `node_modules/bootstrap-icons/font/bootstrap-icons.css` to the `styles` array in `angular.json`.

This app supports what Angular supports by default: current Chrome, Edge, Firefox and Safari, desktop and mobile. Add your own browser list only if you must support something older.

## Wire the stylesheet

`angular.json` — resolve the ITCSS source from the package:

```json
"stylePreprocessorOptions": {
  "includePaths": ["node_modules/@solidaris/styles/src"]
}
```

`src/styles.scss` — the whole system is one `@use`:

```scss
@use '01-settings/settings.prefix' as *;
@use 'main';
```

## Boot the theme

```ts
// src/app/app.config.ts
import { ApplicationConfig, provideZoneChangeDetection } from '@angular/core';
import { provideAnimationsAsync } from '@angular/platform-browser/animations/async';
import { providePlectrum } from '@solidaris/plectrum';

export const appConfig: ApplicationConfig = {
  providers: [
    provideZoneChangeDetection({ eventCoalescing: true }),
    provideAnimationsAsync(),
    providePlectrum(),
  ],
};
```

`providePlectrum()` registers the PrimeNG theme and emits every `--p-*` custom property. The generated `--pds-*` tokens fall back to literals, so styles render even before the theme boots — but PrimeNG components need the provider.

## First component

The sample application renders one Core component around one PrimeNG input. This is `tools/packaging/consumer-app/src/app/app.ts` with the `pInputText` directive added so the PrimeNG theme visibly applies:

```ts
// src/app/app.ts
import { Component } from '@angular/core';
import { InputText } from 'primeng/inputtext';
import { FormFieldComponent } from '@solidaris/ui';

@Component({
  selector: 'app-root',
  imports: [FormFieldComponent, InputText],
  template: `
    <pds-form-field
      label="Member number"
      inputId="member"
      hint="Ten digits, no spaces"
      requiredLabel="obligatoire"
    >
      <input pInputText id="member" type="text" autocomplete="off" />
    </pds-form-field>
  `,
})
export class App {}
```

`ng serve` shows a labelled, themed field: the label and hint come from `pds-form-field` ([Form Field](?path=/docs/custom-components-form-field--docs)), the input chrome from the Plectrum preset. Every `pds-*` component is exported from the `@solidaris/ui` root — the component's docs page names the class to import.

## Build screens

PrimeNG components use the Plectrum preset as-is ([theme gallery](?path=/docs/primeng-actions--docs)). Import Core `pds-*` components from `@solidaris/ui` — [Find a component](?path=/docs/start-here-catalogue--docs) lists each one. Layout with `o-flex` / `o-layout`, chrome with `u-*`, values via `var(--pds-*)`.
