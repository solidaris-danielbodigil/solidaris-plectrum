# At a glance

> **In short.** For reviewers and leads. What Plectrum is, how it is governed and how AI is used — on one screen, with what is proven today and what is not yet. Every figure below is computed from the repository when this Storybook is built.

## What it is

Plectrum is the Solidaris design system for Angular applications: PrimeNG 21 with the Plectrum theme, a small set of Plectrum components, `--pds-*` tokens synchronised with Figma, and a toolkit that gives each application team the same checks, Storybook and editor agents as the core team. It ships as {DISTRIBUTED_PACKAGES.length} packages: {DISTRIBUTED_PACKAGES.filter((pkg) => pkg.role === 'runtime').length} runtime packages that version together and the toolkit.

## How it is governed

- **PrimeNG first.** Plectrum themes PrimeNG and adds a component only when PrimeNG does not cover the need.
- **Teams build locally; Core decides what is shared.** An application team builds its own components without approval. Core answers proposals with a recorded decision and looks for local components worth sharing in the usage reports. [Contribute](?path=/docs/get-started-contribute--docs)
- **Contracts are code.** Each component's metadata drives its documentation page and what agents read; CI fails when code and contract drift. [Process and contracts](?path=/docs/docs-pipeline-contracts--docs)
- **Releases are versioned with their documentation.** Each release publishes its own Storybook. [Releases and versioning](?path=/docs/docs-releases-and-versioning--docs)

## How AI is used

- **As a first reviewer in each application.** The `/plectrum` agent checks reuse before anything is built and answers from the installed catalogue through an offline MCP server. [Use the Plectrum agent](?path=/docs/start-here-use-the-agent--docs)
- **On contracts, not on the whole code base.** Agents read metadata, a generated index and short protocols; the same checks gate their work and people's. [How agents work](?path=/docs/docs-ai-strategy--docs)
- **Measured.** Search quality is replayed on every Plectrum pull request and may not regress; usage and effect are counted without collecting requests or code. [What is measured](?path=/docs/start-here-use-the-agent--docs#what-is-measured)

## Proven, and not yet

Proven by CI on every pull request: automated accessibility checks (WCAG 2.1 AA) on every story, interaction tests on the component stories, keyboard stories for every interactive Plectrum component, packed packages installed and built in a throwaway application, and generated contracts kept in sync with the code.
