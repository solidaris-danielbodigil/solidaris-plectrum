# Contribute

Anyone can contribute, developer or designer, in the core team or an application team.

- **A typo, a broken example, a wrong link:** open a pull request on the Plectrum repository.
- **A missing component, variant or token:** open a [proposal](https://github.com/solidaris-danielbodigil/solidaris-plectrum/issues/new?template=proposal.yml). Describe what the screen must do, what you tried, and link the Figma frame.

Designers draw new components in [PLECTRUM · Custom components](https://www.figma.com/design/IRkr21rHS0w7rI0bgrv1fZ/PLECTRUM-%C2%B7-Custom-components); tokens live in [Plectrum DS · PrimeNG v21](https://www.figma.com/design/wjMnb8GsK8bVKA7UreOJ4L/Plectrum-DS--PrimeNG-v21-).

## Develop and submit a candidate

Create the component in your application with `npm run pds:component -- --name <name>`, then complete its story, unit test and evidence checklist.

To share it with other teams, you need an `approved-candidate` decision. Commit, publish a preview of that commit with its CI result, then run <code>{command('candidateSubmit')}</code>. After a new commit, run it again: the candidate keeps its ID. Once Core accepts it, the component appears in [Find a component](?path=/docs/start-here-catalogue--docs) with a link to your preview.

## Promote existing work

If Core decides to make an accepted candidate a Core component, the core team generalizes it, a designer completes the Figma work, and a release ships it. Your team then upgrades, deletes its local copy and imports the released component. Until then, the component stays yours.

## Register your team

An ID is a short lowercase name: letters, digits and hyphens, starting with a letter. It is separate from the display name. For example, the team ID `ishare` has the label `iSHARE`.

**When:** before your first component submission or usage report. You do not need it to build locally.

**Where:** in the Plectrum repository, file <a href={`${REGISTRY.repository}/blob/main/.ai/contracts/registry.json`}><code>.ai/contracts/registry.json</code></a>.

1. <a href={`${REGISTRY.repository}/edit/main/.ai/contracts/registry.json`}>Edit the file on GitHub</a>.
2. Add your team to `teams` and your application to `applications`:

```json
{ "id": "claims", "label": "Claims", "kind": "application", "reviewer": null }
```

```json
{ "id": "claims-portal", "team": "claims", "label": "Claims portal", "repository": "https://github.com/<org>/<repo>", "kind": "external" }
```

3. Open the pull request. The core team reviews and merges it.

Use the same IDs in your `package.json`.
