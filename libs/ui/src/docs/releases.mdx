# Releases and versioning

Changesets version and publish the three packages together. Applications never track `main` — they install published versions and receive bumps as pull requests.

Related pages:

- [Get started / Use Plectrum in an app](?path=/docs/get-started-use-plectrum-in-an-app--docs) — the consumer side
- [Token pipeline](?path=/docs/docs-token-pipeline--docs) — how token changes reach a release

---

## Process

1. A change lands with a **changeset** (`npm run changeset`) describing the bump (patch / minor / major) and the affected packages.
2. On merge to `main`, the release workflow (`.github/workflows/release.yml`, `changesets/action`) opens or updates the **version PR** — `chore(release): version packages` — accumulating pending changesets into version bumps and changelogs.
3. Merging the version PR publishes with `npm run release` (`changeset publish`) using the `NPM_TOKEN` secret.
4. Application repositories receive the bump as a Renovate / Dependabot pull request (`tools/consumers/renovate.json`).
