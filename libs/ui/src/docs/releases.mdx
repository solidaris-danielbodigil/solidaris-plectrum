# Releases and versioning

Changesets versions the runtime packages together. Package manifests and What's new describe **source** versions. Only the release manifest — `release.json`, recorded by the attended release workflow after the registry and consumer checks pass — proves that a version pair was published.

## Process

1. A change lands with a **changeset** (`npm run changeset`) describing the bump (patch / minor / major) and the affected packages.
2. On merge to `main`, the release workflow (`.github/workflows/release.yml`, `changesets/action`) opens or updates the **version PR**, accumulating pending changesets into version bumps and changelogs.
3. CI packs the artifacts, builds an isolated consumer and checks package ownership, registry target and tarball integrity with `npm run release:check`.
4. A maintainer dispatches the attended release (`.github/workflows/publish-release.yml`) for the exact release ID. It requires the same commit's CI, publishes the exact archives, verifies the actual package visibility, installs them in a clean application, records `release.json` and the contract snapshot, and publishes the matching Storybook.
5. Application repositories receive the bump as a Renovate / Dependabot pull request (`tools/consumers/renovate.json`).
