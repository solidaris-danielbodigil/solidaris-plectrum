# Releases and versioning

The three runtime packages share one version; the toolkit has its own. A version is installable once its release is published — the banner below tells you which version these pages document.

## Process

1. Add a **changeset** (`npm run changeset`) to each change that affects a package: patch, minor or major.
2. When it merges, `.github/workflows/release.yml` opens or updates the **version PR**, which bumps the versions and changelogs.
3. Merge the version PR. CI packs the packages and installs them in a test application (`npm run release:check`).
4. Run `.github/workflows/publish-release.yml` with the release ID (`<runtime>-devkit-<toolkit>`). It publishes the packages, installs them in a clean application, records the release and publishes its Storybook.
5. Application repositories receive the upgrade as a Renovate or Dependabot pull request (`tools/consumers/renovate.json`).
