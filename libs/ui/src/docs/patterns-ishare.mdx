# iSHARE dossier shells

Four page shells live in `apps/ishare` — application compositions of PrimeNG, `pds-*` components and object classes. They are documented here because they carry Card/Tabs token bridges and production BEM blocks, but they are **not** published in `@solidaris/ui`. Promoting one to `libs/ui` is a separate decision (see `docs/component-promotion.md`).

## Composition

- **Affiliate details** — two-column dossier: category tabs (`p-tabs` with the `c-affiliate-details__category-tabs` padding bridge), a documents column (`pds-list` in journey mode behind the sticky documents toolbar) and a detail column (`p-card` panels bridged in `_settings.affiliate-details.scss`).
- **Documents toolbar** — a `pds-toolbar` wearing the `c-affiliate-documents-toolbar` domain class; search (`p-autocomplete`, restyled in `_components.autocomplete.scss`), filter buttons, count badge.
- **Document detail** — stepper, bordered accordion (`c-accordion--bordered`), messages, skeleton loading via `c-skeleton-slot`, and the more-details drawer using `c-timeline--content-only`.
- **Home search panel** — max-width search card composed from `p-card`, `p-autocomplete` and object classes.

## Rules the shells follow

- Domain chrome lives on a **domain BEM class** applied to the shared component (`pds-toolbar` + `c-affiliate-documents-toolbar`) — shared blocks stay generic.
- Feature children on shared blocks prefix the element name (`c-drawer__affiliate-detail-name`), never a nested block (rule `09-styling-policy.md` §9).
- All shell tokens live in `01-settings/_settings.affiliate-*.scss` — nothing is declared in the app.
