# Accordion

<Unstyled>
  <Story of={Stories.Status} />
</Unstyled>

PrimeNG `p-accordion` with the Plectrum theme. Certificate and audit panels add **`c-accordion--bordered`** — a BEMIT modifier already in `libs/styles`. There is no Angular wrapper and no `[border]` input. Put the class on `p-accordion`.

## When to use

- Expandable certificate or audit panels on a dossier
- Stacked sections where one or more panels may be open
- Stock Plectrum accordion when the bordered card stack is not required

## When not to use

- Reimplementing expand / collapse outside PrimeNG
- Overriding `.p-accordionpanel` with hardcoded colour or `!important`
- A `[border]` input on a wrapper that does not exist — write `c-accordion--bordered` on `p-accordion`

## Accessibility

- PrimeNG owns keyboard expand / collapse and panel semantics
- Keep a visible header label on every panel — do not rely on colour or a tag alone
- Disabled panels use `[disabled]` on `p-accordion-panel` so they stay in the tab order contract PrimeNG defines

## Figma

[iSHARE-Audit — bordered accordion](https://www.figma.com/design/9HlAudLC1oesvT8IkrmR6I/iSHARE-Audit?node-id=544-6474)

Constraints:

- PrimeNG owns expand / collapse and the `.p-accordion*` DOM.
- Plectrum owns stock `--p-accordion-*` via `providePlectrum()`.
- `c-accordion--bordered` owns the card-like stack: token bridges in `01-settings/_settings.accordion.scss`, stacked radii in `06-components/_components.accordion.scss`.
- Do not override `.p-accordionpanel` with hardcoded hex or `!important`.

How to write a story for a layer like this: [Writing stories](?path=/docs/docs-writing-stories--docs).
